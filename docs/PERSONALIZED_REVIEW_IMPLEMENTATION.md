## Final-art requirements

The eight Soft 3D candidates have been visually checked over checkerboards and scene plates; all still await human art approval and scene-specific masking. Seven identities need walking and seated variants before their stories can match every narrative action. A separate quiet expression is used for the first candidate on pages 22–24. Page 31 adds exactly two wrapped treats as a separate transparent candidate prop on the unchanged tabletop. Each child needs approved, transparent, style-matched masters with stable face/clothing, unclipped feet, scene-specific poses, and asset versions. Each customer monster needs an approved transparent identity-preserving cutout/pose set. No background removal or generated monster changes are silently inferred.

Current environment plate originals are 1774×887 pixels for a two-page spread. Enlarged copies do not recover print detail. At 17×8.5in those originals are approximately 104ppi; at 300ppi the visible spread needs about 5100×2550 native pixels before bleed. Print-resolution review and replacement masters must preserve the existing approved compositions. No background was regenerated by this increment.

Foreground occlusion masks are not supplied. Pages requesting a behind-foreground placement show an explicit pending note; the review does not pretend to implement a nonexistent mask.

## Image API reference

Transparent PNG output is requested explicitly using `background: "transparent"` and `output_format: "png"`, as documented in [OpenAI image generation](https://developers.openai.com/api/docs/guides/image-generation). The existing configured image model and quality defaults are preserved. No live image API call or real user upload was used in these implementation tests. Alpha validation does not certify faithfulness to the drawing; the parent and admin still review identity.

## Review preview isolation

The review branch includes Node routing middleware plus an entry guard in every API handler. In Vercel preview mode, only deterministic synthetic sample responses are available. The browser disables real uploads and personal-data fields, retains canonical child and binding choices, and provides an explicit sample-book button. Preview requests cannot reach production database, image generation, email, payment or print handlers. Unknown preview mode fails closed. Production behavior passes through unchanged.

These guards have automated local coverage. Browser process-socket restrictions still prevent a local Chromium smoke test. Deployed routing, bundled native dependencies and source files, time/memory and actual renderer behavior must be checked against the exact preview commit. Poppler page-image generation is a local CLI helper, not a server prerequisite for generating the stored PDF package.
